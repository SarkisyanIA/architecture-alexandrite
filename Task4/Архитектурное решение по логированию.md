## Архитектурное решение по логированию

# Мотивация

Мониторинг упростит разбор проблем внутри сервисов и снизит нагрузку поддержки.

Технические метрики:
* Доступность
* Латентность
* Время на анализ воздействия изменений

Бизнес-метрики:
* Среднее время решения проблемы клиентов
* Уровень удовлетворённости клиентов
* Улучшится конверсия

Приоритеты для логирования и трейсинга: 
1. MES API 
2. CRM API
3. Shop API

# Предлагаемое решение

Для хранения и работы с логами мы будем использовать стек ELK (ElasticSearch, Logstash и Kibana) (opensource).

Необходимо настроить аутентификацию. Доступ к логам, включающие чувствительные данные, будут доступны только пользователям с ролью "Поддержка", исходя из принципа минимальных привелегий, другим пользователям не будут даны доступы к логам с чувствительными данными.

Необходимо создать индекс под каждую систему. Логи будут хранится 6 месяцев, после чего будут архивироваться и перемещаться в холодное хранилище. 

# Мероприятия для превращения системы сбора логов в систему анализа логов

Необходимо внердить алертинг, для автоматического оповещения при инцидентах.
Целевая система должна быть такой, чтобы сначала о проблеме узнавала поддержка и разработчики, а не клиенты.
